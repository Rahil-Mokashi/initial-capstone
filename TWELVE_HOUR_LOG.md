### Commit: bank statement reconciliation
- **Models** (migration `e89923afa2bc`): `BankAccount` + per-account payment modes (H-02, a setting per account), saved column layouts per bank, `BankStatementImport`, immutable `BankStatementRow` (unique hash of account+date+amount+narration+reference+balance), `ExpectedReceipt` (derived from the app's own data), `BankMatch`/`BankMatchItem` (confirmed / suggested / void, with who, why, charges; owner lock H-25; kinds match / not_ours / reversal).
- **Import**: CSV and XLSX, header line anywhere, separate debit/credit columns or one signed amount or amount + Dr/Cr, Indian number grouping, dates in common formats. Preview first (stores nothing), then import; duplicate lines are skipped by hash (importing a file twice, or two overlapping files, adds nothing); the running balance is checked line by line (**a missing row shows as a break with the size of the gap**, and the import records it); unreadable lines stop the import unless skipped knowingly. PDF is refused with a plain message (H-07, out of scope).
- **Expected receipts** are generated from the books: each shift's typed Card / DTP Card / Other / PhonePe / Paytm total, each cash deposit (to the account named on the deposit), non-cash credit-customer payments. Date window = takings day + `bank_date_window_days` (default 4, covers T+1 and a weekend). A re-typed total updates the expected amount; a withdrawn record voids it.
- **Matcher** (`bank_matching.py`, pure, deterministic, same answer for any input order): (1) the bank line carries the payment's reference, (2) exactly one amount fits exactly one line inside the window are the ONLY auto-matches; everything else is a suggestion a person confirms: a charge deducted (within `bank_fee_tolerance_percent`, default 2 %, H-09), several payments settled as one credit, one payment arriving in pieces, ambiguous pairings. Reversals (a debit that undoes an earlier credit) are paired; if the credit had been matched the match is undone (unless locked). Manual match / unmatch / reject need a reason; "not the pump's" never forces a match (goodwill business stays out). Everything audit-logged.
- **Screen** "Bank Matching": day by day per mode (expected, received, charges, not matched, status in words), suggestions with both sides and the charge shown, needs-attention list (unmatched credits, expected-but-unseen aged by days, charges so far, statements with missing rows), statement lines with Undo / owner Lock, Import tab with column guessing + saved layouts, Accounts tab with the mode tick-boxes.
